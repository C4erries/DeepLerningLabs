## Задача 5 — MLP. Что и почему

Базовая сеть из `4_3`: 2 слоя (`Linear → ReLU → Linear`), SGD `lr=1e-4`, 500 эпох —
loss падает медленно, accuracy низкая. Доработка:

**Архитектура (4 линейных слоя):**

```
Linear(2 → 128) → ReLU → Dropout(0.1)
Linear(128 → 128) → ReLU → Dropout(0.1)
Linear(128 → 128) → ReLU
Linear(128 → 3)
```

| Параметр | Базовая | Доработанная |
|---|---|---|
| Скрытых слоёв | 1 | **3** |
| Нейронов | 100 | **128** |
| Активация | ReLU | ReLU |
| Регуляризация | — | Dropout 0.1 + weight_decay 1e-4 |
| Оптимизатор | SGD `lr=1e-4` | **Adam `lr=1e-2`** |
| Loss | CrossEntropy (`size_average=False`) | CrossEntropy (`reduction='mean'`) |
| Эпох | 500 | 3000 |
| Accuracy | низкая | **0.9933** |

## Что делает каждая функция / штука

**Тензоры**
- `torch.FloatTensor(3, 4)` — тензор float32 формы (3, 4), значения «мусорные» (память не зануляется). `.zero_()` зануляет на месте.
- `.view(2, 2, 3)` — даёт другую форму без копирования (требует совместимый размер).
- `torch.linspace(a, b, n)` — n равноотстоящих точек от `a` до `b`.
- `.float()` / `.int()` — приведение типа (важно для `mean()`, который требует float).
- `images.float().mean(dim=0)` — усреднение по 0-й оси (по 100 картинкам → одна «средняя»).

**GPU и autograd**
- `torch.device('cuda' if torch.cuda.is_available() else 'cpu')` — переключатель устройства.
- `torch.empty(..., device=device).uniform_()` — равномерное `U[0,1]` сразу на устройстве.
- `.cpu()` — перенос обратно на CPU (нужно для NumPy/matplotlib и `Variable` в старом стиле).
- `Variable(tensor, requires_grad=True)` — обёртка из старого API; сейчас то же даёт `tensor.requires_grad_(True)`. Нужна, чтобы PyTorch запомнил граф вычислений.
- `L.backward()` — обратное распространение по графу; считает `dL/d*` для всех тензоров с `requires_grad=True` и записывает их в `.grad`.
- `c.grad` — градиент L по c.

**MLP (Задача 5)**
- `nn.Module` — базовый класс сети; обязательно `super().__init__()` и `forward(x)`.
- `nn.Sequential(...)` — контейнер, прогоняющий вход через слои подряд.
- `nn.Linear(in, out)` — полносвязный слой `y = xW^T + b`.
- `nn.ReLU()` — `max(0, x)`, нелинейность.
- `nn.Dropout(p)` — на обучении зануляет случайные `p` нейронов, на eval — выключен.
- `nn.CrossEntropyLoss()` — softmax + NLL в одном; принимает логиты и индексы классов.
- `torch.optim.Adam(params, lr, weight_decay)` — адаптивный optimizer; `weight_decay` это L2.
- `net.train()` / `net.eval()` — переключает режимы Dropout/BatchNorm.
- `optimizer.zero_grad()` — обнуляет градиенты (иначе суммируются с прошлого шага).
- `loss.backward()` — заполняет `.grad` у параметров.
- `optimizer.step()` — обновляет веса.
- `with torch.no_grad():` — отключает построение графа (быстрее, меньше памяти; для eval).
- `logits.argmax(1)` — индекс максимума по 1-й оси = предсказанный класс.

**Визуализация решающей границы** — строим сетку точек `meshgrid`, прогоняем через сеть, рисуем `contourf` по предсказанным классам.

## Возможные вопросы

- **Почему 3 скрытых слоя, а не 5/10?** На 600 точках больше слоёв уже переобучаются, dropout не спасает; 3×128 хватает, чтобы выучить спираль до 99.3%.
- **Зачем Dropout, если данных мало?** Регуляризация — снижает зависимость от конкретных нейронов; без него точность на чуть зашумлённых данных проседает.
- **Почему Adam вместо SGD?** Адаптивный шаг по каждому параметру → быстрая сходимость, не надо подбирать `lr` так аккуратно.
- **Что такое `weight_decay=1e-4`?** Это L2-регуляризация: к loss добавляется `λ·∑w²`, мешает весам разрастаться.
- **Почему `loss.backward()` нужен `zero_grad()` перед ним?** PyTorch аккумулирует градиенты в `.grad` (это удобно для gradient accumulation), но при стандартном обучении надо обнулять перед каждым шагом.
- **`view` vs `reshape`?** `view` требует contiguous-память, `reshape` сам скопирует при необходимости.
- **`CrossEntropyLoss` ждёт softmax на входе?** Нет, **логиты** — softmax встроен.
