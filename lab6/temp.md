# ЛР №6 — Transfer Learning (ResNet50 + Flowers102)

Файлы:
- `Lab6_transfer.ipynb` — короткий отчётный ноутбук (только кривые обучения).
- `Lab6_transfer_train.ipynb` — обучение в Colab (GPU). Сохраняет `best_resnet50_flowers.pt` и `history.json`.
- `Lab6_transfer_infer.ipynb` — локальный инференс: метрики, classification_report, confusion matrix, топ путаемых пар, примеры.

## Что делаем

Классификация **Oxford Flowers 102** (102 вида цветов) на базе **предобученной ResNet50**
с весами `IMAGENET1K_V2`. Берём готовый feature extractor, меняем у него последний
полносвязный слой под 102 класса и доучиваем в две стадии.

## Данные

| | |
|---|---|
| train | 1020 (10 на класс) |
| val | 1020 (для обучения объединяется с train) |
| test | 6149 (только для оценки) |
| классов | 102 |
| картинка | 3×224×224 (ресайз под ResNet) |
| batch | 32 |
| нормировка | ImageNet `mean=[0.485, 0.456, 0.406]`, `std=[0.229, 0.224, 0.225]` |
| аугментации train | `RandomResizedCrop(224, scale=(0.7, 1.0))`, `RandomHorizontalFlip`, `ColorJitter` |
| препроцессинг test | `Resize(256)` → `CenterCrop(224)` |

Задача fine-grained: классы похожи между собой (виды одного «объекта» — цветка).

## Архитектура

**ResNet50** — 50-слойная резнет из torchvision (Conv+BN+ReLU → MaxPool → 4 stage'а residual-блоков → GAP → FC).
Структура backbone по stage'ам: `layer1` (3 блока, 256 каналов), `layer2` (4, 512),
`layer3` (6, 1024), `layer4` (3, 2048). Всего **~25.6 млн параметров**.

Поверх неё — наш классификатор: `Linear(2048 → 102)` (заменяем `model.fc`).

## Пайплайн обучения (2 стадии)

| Стадия | Эпох | Что обучается | Optimizer | LR | Scheduler |
|---|---|---|---|---|---|
| 1. warmup | 5 | только `fc` (~210k параметров) | Adam, `wd=1e-4` | `1e-3` | — |
| 2. finetune | 10 | `layer4` + `fc` (~15M параметров) | Adam, `wd=1e-4` | `fc=1e-4`, `layer4=1e-5` | `CosineAnnealingLR` |

- Loss — `CrossEntropyLoss`.
- Сохраняем веса по лучшей test accuracy в `best_resnet50_flowers.pt`.

Итог: test accuracy ≈ **0.87**.

## Зачем две стадии

1. **Warmup.** Если сразу разморозить backbone, градиенты от случайно
   инициализированной головы испортят полезные ImageNet-фичи.
   Сначала «догоняем» голову при замороженном backbone.
2. **Fine-tuning только `layer4`.** Нижние блоки выучили общие фичи (края,
   текстуры) — их трогать вредно. `layer4` — самый «специализированный» под
   ImageNet-классы, его и адаптируем под цветы. Низкий `lr=1e-5` на backbone,
   чтобы не разрушить выученное.

## Что делает каждая функция

**Перенос модели**
- `resnet50(weights=ResNet50_Weights.IMAGENET1K_V2)` — загружает ResNet50 с весами,
  обученными на ImageNet (V2 — улучшенная процедура обучения, ~80.86% top-1).
- `model.fc = nn.Linear(in_features, 102)` — заменяем последний слой; in_features = 2048.
- `for p in model.parameters(): p.requires_grad = False` — заморозка: PyTorch не
  будет считать градиенты по этим параметрам, и optimizer их не обновит.

**Данные**
- `torchvision.datasets.Flowers102(root, split, download, transform)` — стандартный
  датасет; сплиты `train` / `val` / `test`.
- `ConcatDataset([train, val])` — объединяет в один обучающий датасет.
- `transforms.RandomResizedCrop(224, scale=(0.7, 1.0))` — случайный кроп
  (от 70% до 100% площади), затем ресайз до 224. Лёгкая аугментация.
- `transforms.ColorJitter(brightness, contrast, saturation)` — рандомные
  изменения яркости/контраста/насыщенности.
- `transforms.Resize(256)` + `CenterCrop(224)` — стандартный test-препроцесс
  для ImageNet-сетей: ресайз короткой стороны до 256, центральный кроп 224.
- `transforms.Normalize(mean, std)` — обязательная нормировка под статистики ImageNet
  (иначе предобученные веса будут работать хуже).

**Оптимизатор с разными `lr` по группам**
```python
optimizer = torch.optim.Adam([
    {'params': model.layer4.parameters(), 'lr': 1e-5},
    {'params': model.fc.parameters(),     'lr': 1e-4},
], weight_decay=1e-4)
```
`Adam` принимает список словарей — у каждой группы свой `lr`. Голову учим в 10×
быстрее, чем backbone.

- `CosineAnnealingLR(optimizer, T_max=N)` — `lr` плавно по косинусу от стартового к ~0
  за N эпох.

**Цикл обучения** — стандартный: `optimizer.zero_grad()` → `loss.backward()` →
`optimizer.step()`. После каждой эпохи: eval на тесте, сравнение с best, чекпойнт.

**Метрики (infer)**
- `sklearn.metrics.classification_report` — precision/recall/F1 по каждому из 102
  классов + macro/weighted средние.
- `sklearn.metrics.confusion_matrix` — матрица 102×102. Рисуем в log-scale, потому
  что значения сильно различаются.
- **Топ путаемых пар** — берём матрицу, зануляем диагональ, сортируем
  off-diagonal по убыванию.
- `denorm(t)` — обратная нормировка для отрисовки картинок (умножаем на std,
  прибавляем mean).

## Возможные вопросы

- **Что такое Transfer Learning?**
  Используем веса сети, обученной на одной (большой) задаче, как старт для другой
  (обычно меньшей). Экономит время, даёт высокую точность на маленьких выборках.
- **Почему именно ResNet50, а не VGG/MobileNet?**
  ResNet — стандартный baseline, residual-соединения позволяют учить глубокую сеть
  без проблемы затухания градиентов. 50 слоёв — компромисс между качеством и скоростью.
- **Сколько слоёв в ResNet50?**
  50 «весовых» слоёв: 1 начальная свёртка + 3+4+6+3 residual-bottleneck блоков
  (в каждом 3 свёртки) + 1 FC = 1 + (3+4+6+3)·3 + 1 = 50.
- **Что такое residual-блок?**
  `output = F(x) + x` — выход блока складывается со входом. Решает проблему
  затухания градиентов в глубоких сетях.
- **Зачем замораживать backbone?**
  В стадии 1 голова инициализирована случайно — её градиенты «зашумлены» и
  разрушают полезные ImageNet-фичи backbone.
- **Почему разморозили именно `layer4`?**
  Нижние слои выучили общие фичи (края, текстуры) — они одинаково полезны для
  любых картинок. Верхний `layer4` — самый task-specific под ImageNet-классы,
  его и адаптируем под цветы.
- **Зачем разные `lr` для головы и backbone?**
  Backbone уже почти оптимален — нужны маленькие шаги (`1e-5`). Голова с нуля —
  ей нужны бóльшие шаги (`1e-4`).
- **Зачем нормировка под ImageNet?**
  Сеть училась на этой статистике; если подать ненормированные картинки,
  активации сместятся, и предобученные веса перестанут работать корректно.
- **Что такое fine-grained классификация?**
  Различение очень близких подклассов (виды цветов, породы собак) — границы
  размытые даже для человека, и обычно стандартные accuracy ниже, чем у обычной
  классификации.
- **Почему accuracy ~0.87, а не ~0.95?**
  Fine-grained задача + всего ~2040 train-картинок на 102 класса (≈20 на класс).
  По confusion matrix видно, что путаются визуально близкие виды.
- **Что такое `weight_decay`?**
  L2-регуляризация: к loss добавляется `λ·∑w²`, мешает весам разрастаться.
- **Чем `RandomResizedCrop` отличается от `RandomCrop`?**
  `RandomCrop` вырезает фиксированный размер из исходной картинки; `RandomResizedCrop`
  вырезает случайный кусок и ресайзит до целевого размера — это сильнее
  «джиттерит» масштаб.
